状态 进入方式 该状态可见的内容

四、功能需求

4.1 头图与进入正文

  • 进入页面时，头图占据整个可视区域，正文（倒计时 / Tab / 榜单）需要向下滑动才能看到。
  • 头图内包含：主题标题（主标题 + 副标题）、Rule 按钮。

4.2 Rule 按钮与规则弹窗（S6）

  • 点击头图上的 Rule 按钮 → 打开规则弹窗，内含标题与 6 条规则正文。
  • 弹窗内的「×」按钮、或点击弹窗外遮罩 → 关闭弹窗并回到 S1 本周榜。
  • 规则 6 条的文案见原型；业务含义与原版线上规则逐条对应，仅措辞按主题包装。

4.3 Tab 切换

  • 三个 Tab 互斥选中：This week → S1；Award → S4；Last week → S5。
  • 切换 Tab 后，页面内容切换为对应状态的内容（见第三节），选中态同步变化。
  • 从其他 Tab 切回 This week 时，榜单数据需重新渲染。

4.4 倒计时

  • 展示「天 / 时 / 分 / 秒」四段，每秒递减，归零后停在 0（不出现负数）。
  • 时间基准必须使用接口返回的服务器时间（sysTime）校准，不得直接使用本机时间。
  • 距离结束不足 24 小时时，倒计时进入强调态（具体视觉由设计定），用于制造紧迫感。
  • 在 S5 上周榜状态下不展示倒计时。

4.5 领奖台（Top 3）

  • 展示本周榜第 1~3 名；每个名次展示一对 CP（双头像）+ CP 名 + 分值。
  • 排列顺序固定为 2-1-3（第 1 名在中间），不因数据缺失而错位。
  • 在 S1 与 S5 两个状态下均展示。

4.6 榜单列表（第 4 名起）

  • 从第 4 名开始逐条展示；每行包含：名次、双头像、CP 名、分值。
  • 分页沿用现状：每次请求 limit = 30，触底自动加载下一页；数据不足一页时判定为到底，停止请求。
  • 长昵称需截断省略（不得撑破布局或换行）。

4.7 底部「我的排名」条

  • 仅在本周榜（S1）展示，切到奖励页 / 上周榜时不出现。
  • 点击行为：该条为纯信息展示，点击不唤起任何弹层（原版的点击弹层已取消）。
  • 无 CP 场景：该条只展示「Find Your CP」文案，纯展示 —— 点击无跳转、无弹层、状态不变（2026-10-14 产品确认）。

文案随用户与 CP 的关系变化，共 4 种场景：

场景 展示内容
未上榜（名次 > 10）「My Rank」+ 我的名次与分值 +「距离上榜还差 x」
已上榜（名次 2~10）「My Rank」+ 我的名次与分值 +「距离上一名还差 x」
TOP 1（名次 = 1）「My Rank」+ 我的名次与分值，不展示任何文案
无 CP只展示「Find Your CP」文案；不展示名次、分值与火候值
  • 取值口径：未上榜的「差 x」= 第 10 名分值 − 我的分值；已上榜的「差 x」= 上一名分值 − 我的分值；差值需做格式化（千分位）。
  • 切换语言（en ⇄ ar）后，上述文案需立即跟随刷新。

4.8 奖励页（S4）

  • 展示三张奖励档位卡：TOP 1 / TOP 2~5 / TOP 6~10，每张卡内展示该档位的奖品（排布方式由设计定）。
  • 奖品名称过长时单行省略；奖品较多时卡片高度自适应撑开，不出现卡片内部滚动条。
  • 奖励数据来源沿用 /shop/productRankReward/getByType（type=2）。

4.9 上周榜（S5）

  • 与本周榜同构（领奖台 + 列表），但不展示倒计时，且不展示底部「我的排名」条。
  • 页面展示「上周榜」标题与「榜单已封印」提示文案。
  • 数据来源沿用 rankingListType=2。

六、数据与接口（全部沿用现状，不变更）

接口 用途 关键参数
GET /revenue/couple/v2/getRankConfig活动周期 + 服务器时间返回 start / end / sysTime（倒计时校准依据）
GET /revenue/couple/v2/rank榜单列表index / limit（默认 30）/ rankingListType（0=本周，2=上周）

字段语义（不变）：

字段 含义 前端表现
loveValueCP 之间互赠 CP 礼物的金额（榜单分值）榜单分值展示

statusCP 关系状态；0 = 已解除沿用线上现状（本期不新增表现）
rank名次≤ 3 进领奖台，> 3 进普通列表
  • ⚠️ 以上接口均需登录态（匿名访问返回 status:1010），联调时请准备登录账号。

七、文案与多语言

  • 页面文案以原型为准（原型中双击即可查看 / 编辑全部文案，共 30+ 条）。
  • 需支持 en / ar 两种语言；ar 为从右到左（RTL）布局，镜像需覆盖弹窗、列表、倒计时等全部模块。
  • 新增文案需在两种语言下均无缺失；切换语言后动态文案（底部条差值、倒计时标签等）需同步刷新。

九、边界与异常

  • 榜单无数据：列表区域不出现空白错位（沿用线上现状处理）。
  • 分页到底：不再发起请求，不出现重复行。
  • 长昵称 / 长奖品名：截断省略，不得撑破布局。
  • 倒计时边界：活动未开始 / 已结束（duration = 0）时不得出现负数或 NaN。
  • 语言切换：切换瞬间不得出现文案缺失或布局跳动。
  • 网络异常：请求失败时保持页面可用（沿用线上现状处理）。
