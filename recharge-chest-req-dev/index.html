四、功能需求

4.1 首屏 Hero 与进入正文

  • 进入页面时头图占据整个可视区域，正文需要向下滑动才能看到。
  • 头图内有三个可交互 / 展示元素：规则入口按钮、TOP1 展示卡、结算倒计时。
  • 头图资源自带（已做）动画，本期不再另做开屏动画，开发不新增开屏流程。
  • 首屏底部不放任何下滑提示，仅保留版权行。

4.2 规则入口与规则页（S8 / S9）

  • 点首屏的「Rules」按钮 → 打开规则页（覆盖层），默认停在「宝箱规则」页签。
  • 规则页内两个页签互斥：「宝箱规则」（6 条）/「榜单规则」（5 条），正文直接展开、不折叠。
  • 页内「×」按钮或点击弹窗外遮罩 → 关闭规则页，回到打开它时的状态。
  • 规则文案必须与 6.3 逐字一致；文案来自配置，不由前端硬编码。

4.3 Tab 切换

  • 两个 Tab 互斥选中：Chests → 显示宝箱内容；Ranking → 显示榜单内容。
  • 切换后 Tab 选中态与页面内容同步变化（见第三节）。
  • 吸底条随 Tab 变化：宝箱 Tab 显示吸底 CTA（4.8），榜单 Tab 显示吸底「我的排名」条（4.11），两者不同时出现。
  • 从榜单 Tab 切回宝箱 Tab 时，宝箱轮播的选中档与进度需按当前充值额重新计算并渲染。

4.4 结算倒计时

  • 展示「天 / 时 / 分 / 秒」四段，每秒递减；归零后停在 0，不出现负数。
  • 时间基准以沙特时间为准：目标时刻 = 当月最后一天 19:00 沙特时间（= 16:00 UTC）。
  • 必须在倒计时下方给出时区标注（「Saudi time (GMT+3)」/「بتوقيت السعودية (GMT+3)」），避免用户对不上"月末"的理解。
  • 时间基准应使用接口返回的服务器时间校准，不得直接使用本机时间。
  • 距离结束不足 24 小时时进入强调态（具体视觉由设计定）。
  • 榜单头内不再重复放置倒计时（首屏已有，重复会出现两处数字不一致）。

4.5 进度卡

  • 展示当前充值额、当前档门槛、以及两者差额；三者由同一份状态派生，不得各算各的。
  • 差额文案「还差 $X 解锁 LVn」在进度卡与吸底 CTA 两处同时常驻，两处数值必须一致。
  • 达到门槛时该档显示为已完成态。
  • 切档或充值后，进度卡、奖励面板、CTA 文案三处同步重建。

4.6 宝箱轮播

  • 5 个档位横向排列，可左右滑动；滑动停稳后停在中央的档位即被选中（无需点击）。
  • 选中的宝箱必须停在中央，左右相邻档对称分布。
  • 默认定位：进入页面时自动定位到「最接近的未解锁档」并居中，无需用户操作。
  • 点亮 ≠ 选中：点亮由「是否达到门槛」决定；选中由「滑动停在哪」决定，两者独立。
  • 达到门槛的档才点亮；未达门槛的档为未点亮态（含被选中的未达门槛档）。
  • 点选或滑停选中某档后，奖励面板、进度卡、CTA 文案同步更新。

4.7 宝箱奖励面板

  • 面板随当前选中的档位重建，展示该档的全部奖励项。
  • 每档固定 4 项：头像框 / 坐骑 / 勋章 / VIP 等级（LV1、LV2 的勋章为无动效版）。内容与 2.3 的表格一致。
  • 未解锁时奖励一律完整展示：不加蒙版、不降透明度、不显示中央锁标；锁定状态只由面板上的 Locked / Unlocked 徽标表达。
  • 奖励项的排布方式由设计定；内容、数量与顺序（按 2.3 表格从左到右、从上到下）不得改动。
  • 该档奖励列表为空时，隐藏奖励格区域，保留面板与文案。
  • 奖励卡形态由接口字段 type 决定：type = 36 → 竖版大卡；type = 35 → 横版长条；其余 → 宫格。前端需按 type 正确分流，不得写死某一种形态。
  • ⚠️ 本次奖励重置后，各奖励项实际配置的 type 值待后台确认（见 9.2）。

4.8 吸底 CTA 与充值页

  • 吸底 CTA 仅在宝箱 Tab 展示。
  • 点击 CTA → 从底部拉起「充值页」（提起式窗口，不是居中弹窗）。
  • 充值页内容：分区标题「Diamond」+ banner 位 + 4 个充值档位行（左＝钻石数量、右＝价格按钮）。
  • 当前 4 档：3000 / $0.99、15000 / $4.99、45000 / $14.99、152500 / $49.99。档位与价格由配置下发，前端按返回渲染。
  • 点价格按钮 → 按该金额发起一笔充值；充值成功后关闭充值页，并按新的充值额刷新进度、宝箱点亮、奖励面板与 CTA。
  • 页内「×」按钮或点击上方遮罩 → 关闭充值页。
  • 全部档位解锁后，CTA 文案变为「去冲榜」，点击直接切到榜单 Tab。

⚠️ 与旧行为的差异：现版点 CTA 是「一键补足差额」，本期改为先打开充值页由用户选档，这一处交互变化需重点回归。

4.9 榜单头与排名奖励弹窗（S7）

  • 榜单头展示标题与榜单口径说明，并在头内提供「Ranking Rewards」入口。
  • 点该入口 → 打开排名奖励弹窗（覆盖层）。
  • 弹窗按名次展示三行：TOP1 / TOP2 / TOP3，每行展示该名次的奖励项。
  • 项数固定为 TOP1 = 7 项、TOP2 = 6 项、TOP3 = 6 项；内容见 2.3。
  • 弹窗「×」按钮或点击遮罩 → 关闭弹窗并回到榜单 Tab。
  • 接口返回空时需有明确空态，不得出现空白弹窗。

4.10 领奖台 TOP1~3 与榜单列表（第 4 名起）

  • 领奖台展示第 1~3 名；第 1 名居中，第 2、3 名分列两侧。
  • 每名展示：头像 + 昵称 + 充值额。
  • 不足 3 人时，空位渲染占位（??? + 默认头像 + 0），不隐藏整块。
  • 从第 4 名起逐条展示；每行包含名次、头像、昵称、充值额。
  • 无数据时渲染占位行，榜单区域不得出现空白塌陷。
  • 昵称脱敏：保留前 2 位 + ****（现版有该过滤器但从未接线，本期需接线；如未确认则不脱敏 —— 见 9.2）。
  • 吸底条只展示 4 项：用户头像 / 排名 / ID / 已充值金额；未上榜时名次显示 -。

4.11 吸底「我的排名」条

  • 仅榜单 Tab 展示；宝箱 Tab 不出现（宝箱 Tab 的吸底是 CTA，见 4.8）。
  • 展示用户头像、排名、ID、已充值金额；未上榜时名次显示「-」。
  • 该条为纯信息展示，点击不唤起任何弹层、不跳转。

4.12 首屏 TOP1 展示卡

  • 展示榜单月榜第 1 名的头像与 ID；纯展示，不可点击。
  • 无数据时保留外框，头像与 ID 置空为「—」；不隐藏整卡。

4.13 空态

  • 榜单无数据：展示空态提示，不出现空白错位。
  • 宝箱奖励列表为空：隐藏奖励格区域，保留面板与文案。
  • 排名奖励接口为空：弹窗内展示空态，不出现空白弹窗。

4.14 参与资格与计入口径（沿用现状，前端不参与计算）

  • 本活动仅普通用户可参与，代理商（Reseller）不可参与。
  • 直接计入的来源：Google Pay / Apple 内购 / 站内三方支付 —— 都直接计入活动累计额。
  • 用户向代理商购买钻石也计入，折算口径为「用户从平台拿到同等数量钻石所需要的价格」，即 用户侧零售价（以平台自身的钻石价目表为准），不是代理商的进货价。
  • 以下两项不计入：① 代理商自己给自己充值；② 工资充值（Salary recharge）。
  • ⚠️ 以上四条口径的判定与折算全部在后端完成。前端不参与任何折算、判定或过滤，只展示接口返回的充值额；本期换皮不改变这套口径，开发无需在前端实现判断逻辑。
  • 界面规则文案必须与本条口径一致：宝箱规则 rule.c1 / rule.c3 与榜单规则 rule.r4 见 6.3，其中 rule.c3 与 rule.r4 必须逐字相同。

⚠️ 与线上旧文案的差异：旧句为「counted based on the price he got from the platform」，其中 he 会被读成「代理商拿到的价」，与上面「用户侧零售价」的口径相反；本期已改写为无歧义的「the price a user would pay on the platform for the same quantity of diamonds」。两种读法下折算金额不同（用户侧零售价 > 代理商进货价），口径与验收均以新版文案为准。

六、文案与多语言

  • 页面文案以原型为准（原型中双击即可查看 / 编辑全部文案，共 80+ 条）。
  • 需支持 en / ar 两种语言；ar 为从右到左（RTL）布局，镜像需覆盖弹窗、规则页、充值页、榜单、倒计时等全部模块。
  • 奖励项名称、VIP 等级、时区标注等也要跟随语言切换；VIPn 为专有名词，两种语言下都写作 VIPn。
  • 切换语言后，动态文案（差额、倒计时标签、toast 等）需立即跟随刷新。
